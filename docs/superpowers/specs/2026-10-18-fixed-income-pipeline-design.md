# 固定收益数据流水线设计

## 目标

为现有固定收益项目增加一条可重复运行、失败即停止、结果可追溯的自动流水线。流水线负责获取或读取数据、标准化、执行质量检查、生成分析报告，并为每次运行保存质量报告和产物清单。

本轮不增加邮件发送、投资推荐、操作系统定时任务或新的网页抓取器。实时网络数据只在本机显式运行；CI 使用仓库内的合成数据，避免上游网络波动造成假失败。

## 用户入口

新增命令：

```bash
fixed-income-lab pipeline --source demo
fixed-income-lab pipeline --source official --start 20261001 --end 20261017
```

支持 `official`、`akshare` 和 `demo` 三种来源。`official` 与 `akshare` 必须提供日期范围；`demo` 仅用于断网演示和自动测试，并在所有输出中明确标记为合成数据。

## 数据流

```text
来源适配器
  → 统一长表
  → 数据质量门禁
  → 标准化 CSV
  → Markdown / Excel 报告
  → data_quality.json
  → manifest.json
```

每次运行写入独立目录。所有内容先写入同一目标目录下的临时目录；全部检查和导出成功后再原子重命名为最终目录。失败时删除临时目录，不留下看似成功的半成品。

## 质量门禁

收益率曲线必须满足：

- 必需字段存在，日期、期限和收益率可解析。
- `date + tenor_years` 唯一。
- 收益率在 `-5%` 到 `30%` 之间，期限在 `0` 到 `100` 年之间。
- 数据行、交易日和期限数量不为零。
- 官方主数据必须包含来源 URL、原始文件 SHA-256、UTC 获取时间和 `official_primary` 状态。
- 合成数据必须明确标记，不允许在官方模式中静默回退使用。

一级发行和市场事件允许为空，但必须保留正确字段结构。空数据在报告中明确显示为“暂无已录入”，不得使用合成记录补齐。

## 运行产物

每次成功运行包含：

- `normalized_yield_curve.csv`：标准化长表。
- `fixed_income_brief_*.md`：晨报。
- `fixed_income_brief_*.xlsx`：多工作表数据包。
- `data_quality.json`：检查结果、行数、日期范围、期限、来源和数据状态。
- `manifest.json`：运行参数、程序版本、开始/结束时间和每个产物的 SHA-256。

清单不保存密钥、环境变量值或原始文件正文。

## 模块边界

- `quality.py`：只负责纯数据校验和质量摘要，不访问网络、不写文件。
- `pipeline.py`：编排来源、校验、导出和原子发布。
- `cli.py`：解析参数并调用流水线，不复制业务逻辑。
- 现有 `data.py`、`report.py` 和来源适配器保持职责不变。

## 错误处理

来源失败、字段变化或质量检查失败均返回非零退出码。错误信息包含阶段和原因，但不打印密钥或数据正文。缓存仅按现有显式规则使用；不存在缓存时不得静默切换到演示数据。

## 验证

- 单元测试覆盖正常数据、缺字段、重复键、异常范围和官方来源元数据。
- 端到端测试运行 `demo` 流水线，核对五类产物、清单哈希和临时目录清理。
- CI 在 Python 3.11 和 3.12 上运行全部测试，并执行一次离线流水线冒烟测试。
- 本机额外运行一次官方数据流水线；若上游不可达，明确报告网络限制，不以演示结果冒充官方运行成功。

## 后续批次

固定收益流水线验收后，再为仓储项目增加训练数据漂移报告和模型指标回归门禁。其他项目不在本批次修改，避免同时改变多个业务边界。
